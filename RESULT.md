## October 7: notebooks run inside ros.ai

Adam's fourth Stage One foundation ask: a Notebook block opens a notebook directly, or from an imported file, with ros.ai's own screen and Python running inside ros.ai. On the October 6 decision card he chose the Docker sandbox for that Python. This replaces the October 2–3 connection to a separately run Jupyter server.

- **Screen.** A Notebook block opens over the canvas (double-click, **Open notebook**, or straight after **Add block → Notebook**); **Canvas** goes back while Python keeps running. Code cells use the Code block's editor (highlighting, completion, and an underline on the line that failed); text cells show Markdown and edit on double-click. The toolbar has Run, Run all, Stop, Restart, + Code, + Text, Clear outputs and Import .ipynb, with Python's state, the permission choice and the save state. Jupyter's keys work: Shift+Enter, Ctrl/⌘+Enter, and after Esc: A, B, M, Y, D D, Z, J/K or the arrows, and Enter.
- **Python.** Each notebook gets one long-running Python in the Code blocks' Docker image, so variables carry from cell to cell until Restart. It has no network, a read-only system, no privileges, 2 GB of memory, 2 CPUs and 128 processes; it can read the project folder and write only in `outputs/<notebook>/`. Output appears as it is printed. Stop interrupts the running cell and keeps the variables. Up to four notebooks keep Python running, and one left unused for 30 minutes stops and says so.
- **Permissions.** Each cell passes the project's permission choice before it runs. Ask every time shows a check card on the cell; Approve for me runs plain analysis code and asks before anything else, remembering names that earlier cells defined; Full access runs every cell, still inside the sandbox.
- **Files.** The notebook is saved as `notebooks/<name>.ipynb` in the project folder, written exactly as Jupyter writes it, so Jupyter or VS Code can open it. A save from another app reloads the open notebook with Undo; if ros.ai still holds unsaved typing, it asks which version to keep. **Import .ipynb** (in Add block or on the toolbar) brings in a notebook with its outputs, and replacing a notebook can be undone. An older Notebook block starts from its newest saved snapshot.
- **Outputs.** Tables, text, errors, PNG and SVG figures, Markdown and CSV are shown. HTML other than tables, scripts and pictures from the web are never loaded. **Save as result** keeps an output for **Use as input** or **Use in report**. Only an output that ros.ai's sandbox produced counts as a measured result; an imported or outside-edited output is labelled as such.
- **Card.** The canvas card shows the cell count, the last run (Ran, Error in or Stopped, with its number) and the newest figure, a number, or the first cell's text. A notebook still running after it was closed shows Running until it finishes. Cards with a figure (Code blocks' too, by the same rule) now grow to show it instead of a thin slice.

Verified in Chromium against an isolated data directory, with the Docker image built locally and real runs: opening from the card; Run all ran to a ZeroDivisionError, underlined its line and left the next cell unrun; Stop ended a printing loop with KeyboardInterrupt and kept Python; typing in a new cell and pressing Shift+Enter printed 84 and opened the next cell; Esc then B, D D, Z, M, Y, K and Enter did what they say; Save as result offered Use as input with this project's blocks, and Use in report opened the report editor with the output linked. A Jupyter-made `.ipynb` (Markdown with a list, a table and a formula, a pandas table, a `\r` progress line, a PNG figure, an error with colour codes and a raw cell) imported as a new block and rendered correctly; importing over a notebook and pressing Undo restored it; an outside edit reloaded with Undo; Ask every time showed the check card and ran after approval; Approve for me ran a plain pandas cell without asking and held `import subprocess`. A notebook closed mid-run showed Running on its card, then Ran [1]. The check found and fixed two problems: in React's development mode the cursor did not land in a newly added cell, and figure cards showed only a sliver of the figure. Earlier API checks confirmed that the saved file matches Jupyter's writer byte for byte. Not verified: Docker Desktop on a Mac (folder sharing and file ownership in `outputs/`) and Windows. `tsc --noEmit` and `npm run build` pass; the unit suite was not run, and no paid calls were made.

## October 6: project folders

Adam's fifth Stage One ask, on the same branch: each project's blocks are ordinary files in a folder the person chooses, so Obsidian, VS Code or Jupyter can open them.

- **Choosing the folder.** New project asks for a folder, prefilled with `~/Documents/ros.ai/<project name>`; **Choose…** opens the computer's own folder window (macOS, or Linux with zenity/kdialog), where a new folder can also be made. ros.ai creates the folder if needed and refuses the home folder, system folders, Documents or Desktop themselves, its own files, and a folder that overlaps another project. **Open a folder** in New project reopens a folder ros.ai made, with its blocks, layout and connections, even on another computer; any other folder becomes a project whose files the person adds. Existing projects show **Choose a folder** in the header and are unchanged until one is chosen.
- **Layout.** `notes/` (Markdown), `code/` (`.py`, or the language's extension), `notebooks/` (`.ipynb`), `data/` (CSV), `figures/`, `reports/` (Markdown whose evidence links point at the exported files), `outputs/<Code block>/` (the latest completed run; tables as CSV), `<project>.canvas` (JSON Canvas, so Obsidian shows the board) and `.ros-ai/project.json`.
- **Two-way sync.** Saving in ros.ai rewrites the file. An edit saved in another app becomes a canvas change within a few seconds, labelled "Edited outside ros.ai: …", which Undo reverses. Renaming a file renames its block. A deleted file is marked **File missing** on its card and can be put back from the folder dialog. Files dropped into the folder are listed there and become blocks only when added. Removing a block moves its file to `.ros-ai/trash/<date>/`. ros.ai never overwrites a file that changed elsewhere before it has read the change, and an open Code editor with unsaved edits asks whether to use the new version or keep its own.
- **ros.ai's own records** now default to the computer's app-data folder (macOS `~/Library/Application Support/ros.ai`). A checkout that already has `.ros-ai/` keeps using it, and `ROS_DATA_DIR` still wins.
- **Local API hardening** (roadmap gap 1): non-GET `/api` calls must send JSON, cross-site browser requests are refused, and agent setup is a POST.
- **`npm run try -- <pull request>`** starts a pull request on localhost in a separate worktree with its own packages and empty data, without switching branches or touching the person's projects and keys.

Verified in Chromium against an isolated data directory: the New project folder follows the typed name; creating the project wrote the folder, manifest and board; a new Code block showed `code/Code.py`; `Ctrl+S` wrote the file; a file edit appeared in the open editor; with unsaved edits the editor kept them and offered the new version; deleting the file marked the card and **Put the file back** restored it; a note dropped into `notes/` was added from the folder dialog; **Open a folder** on a plain folder made a project with its two files waiting; `/etc` was refused with a reason. Through the API: a Docker run wrote `outputs/Code/Answer.json` and `Small table.csv`; a copied folder opened in a second, empty instance with both blocks and their positions; after the folder was moved, its status said so and opening the new place reconnected the same project. Earlier API checks covered Undo of outside edits, renames both ways, trash and restore, atomic saves from editors, and refusals. Not verified: the macOS folder window and Finder reveal (this check ran on Linux without a display) and Windows. `tsc --noEmit` and `npm run build` pass; the unit suite was not run, and no paid calls were made.

## October 3: direct Code editor

Code blocks now use a CodeMirror 6 editor instead of a plain textarea. **Add & write code** adds the block, reveals it on the canvas and opens the editor with the cursor in the program. The editor highlights Python and suggests, as you type, ros.ai helpers with their signatures, `pd`/`np`/`plt`/`scipy`/`df` members, CSV column names after `df["`, and parameter keys after `params["`. ## Delivered behavior

- **Code** is created and revealed on the canvas first, then its editor opens; the open arrow at its top right or a double-click reopens it later, and Esc closes it. The card shows the source, scrollable in place. The editor has Run/Save (Stop while running), the program, an Inputs section (zero/one explicit full CSV, JSON parameters, language), and a Results column with outputs/errors, earlier attempts and the full attempt record. Python executes only in the existing Docker boundary. No selected dataset supplies neither a sample artifact nor `df`. Other languages retain source but have no execution adapter.
- Saved code/settings are ordinary undoable workspace content; browser-local unsaved drafts survive reopening. Layout does not consume content history or discard redo. Failed attempts retain program, logs/errors and valid bounded outputs produced before failure; earlier attempts stay immutable. Ask reviews the exact captured attempt and checks saved source/settings before admission. Resource/cancellation behavior and uncertainty accounting remain intact.
- **Notebook** (as delivered October 2) connected to a user-managed Jupyter server and captured saved outputs as external records. Since October 7 a notebook runs inside ros.ai instead (see the top of this file); outputs captured the old way keep their external-capture labels.
- CSV, JSON, text/logs, validated PNG and conservative safe SVG previews are supported. Unsupported MIME remains escaped, labelled inert JSON with exact download; HTML/scripts are never rendered.
- Both block types use the existing artifact/history store. **Use as input** previews the exact version and same-project destination, records the selection receipt, and starts no recipient work. Only a full CSV becomes Code's single `df` input; other formats stay selected evidence. Source edits mark old output stale where evidence allows, without switching receiver/report versions or recomputing.
- **Use in report** preserves exact evidence IDs/hashes and external-versus-measured attribution in saved reports/exports. **Interpret selected output** prepares only the deliberately selected textual output and structural destination through the existing guide context/consent flow. No whole notebook, neighboring cells or project conversation is added implicitly; no live model request was verified.
- Blank/manual projects keep Assistant closed. Code/Notebook creation is directly discoverable on the existing canvas; **Discuss** retains the separate node conversation. Knowledge/Action/Group content remains compatible. Manual Code/Notebook cards show useful captured outputs without an inherited inference model badge.

## Unsupported behavior

C/Haskell execution, multi-CSV Python inputs, arbitrary container-file import, notebook kernels other than ros.ai's Docker Python, cross-project reuse, arbitrary agent delivery and managed Nemotron packaging/training are unsupported. Plot-to-model interpretation is unavailable in the text-only guide; deliberately selected text/CSV/JSON evidence can be prepared.

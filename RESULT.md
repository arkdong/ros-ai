## October 6: project folders

Adam's fifth Stage One ask, on the same branch: each project's blocks are ordinary files in a folder the person chooses, so Obsidian, VS Code or Jupyter can open them.

- **Choosing the folder.** New project asks for a folder, prefilled with `~/Documents/ros.ai/<project name>`; **Choose…** opens the computer's own folder window (macOS, or Linux with zenity/kdialog), where a new folder can also be made. ros.ai creates the folder if needed and refuses the home folder, system folders, Documents or Desktop themselves, its own files, and a folder that overlaps another project. **Open a folder** in New project reopens a folder ros.ai made, with its blocks, layout and connections, even on another computer; any other folder becomes a project whose files the person adds. Existing projects show **Choose a folder** in the header and are unchanged until one is chosen.
- **Layout.** `notes/` (Markdown), `code/` (`.py`, or the language's extension), `notebooks/` (`.ipynb`), `data/` (CSV), `figures/`, `reports/` (Markdown whose evidence links point at the exported files), `outputs/<Code block>/` (the latest completed run; tables as CSV), `<project>.canvas` (JSON Canvas, so Obsidian shows the board) and `.ros-ai/project.json`.
- **Two-way sync.** Saving in ros.ai rewrites the file. An edit saved in another app becomes a canvas change within a few seconds, labelled "Edited outside ros.ai: …", which Undo reverses. Renaming a file renames its block. A deleted file is marked **File missing** on its card and can be put back from the folder dialog. Files dropped into the folder are listed there and become blocks only when added. Removing a block moves its file to `.ros-ai/trash/<date>/`. ros.ai never overwrites a file that changed elsewhere before it has read the change, and an open Code editor with unsaved edits asks whether to use the new version or keep its own.
- **ros.ai's own records** now default to the computer's app-data folder (macOS `~/Library/Application Support/ros.ai`). A checkout that already has `.ros-ai/` keeps using it, and `ROS_DATA_DIR` still wins.
- **Local API hardening** (roadmap gap 1): non-GET `/api` calls must send JSON, cross-site browser requests are refused, and agent setup is a POST.
- **`npm run try -- <pull request>`** starts a pull request on localhost in a separate worktree with its own packages and empty data, without switching branches or touching the person's projects and keys.

Verified in Chromium against an isolated data directory: the New project folder follows the typed name; creating the project wrote the folder, manifest and board; a new Code block showed `code/Code.py`; `Ctrl+S` wrote the file; a file edit appeared in the open editor; with unsaved edits the editor kept them and offered the new version; deleting the file marked the card and **Put the file back** restored it; a note dropped into `notes/` was added from the folder dialog; **Open a folder** on a plain folder made a project with its two files waiting; `/etc` was refused with a reason. Through the API: a Docker run wrote `outputs/Code/Answer.json` and `Small table.csv`; a copied folder opened in a second, empty instance with both blocks and their positions; after the folder was moved, its status said so and opening the new place reconnected the same project. Earlier API checks covered Undo of outside edits, renames both ways, trash and restore, atomic saves from editors, and refusals. Not verified: the macOS folder window and Finder reveal (this check ran on Linux without a display) and Windows. `tsc --noEmit` and `npm run build` pass; the unit suite was not run, and no paid calls were made.

## October 3: direct Code editor

Code blocks now use a CodeMirror 6 editor instead of a plain textarea. **Add & write code** adds the block, reveals it on the canvas and opens the editor with the cursor in the program. The editor highlights Python and suggests, as you type, ros.ai helpers with their signatures, `pd`/`np`/`plt`/`scipy`/`df` members, CSV column names after `df["`, and parameter keys after `params["`. Lines Python cannot parse get a wavy underline. After a failed attempt, the line that raised the error is underlined while the editor still holds that attempt's code. `Ctrl/⌘+Enter` runs and `Ctrl/⌘+S` saves. Empty blocks offer starter programs, and helper chips insert calls at the cursor. Parameters use a small JSON editor. Experiment code in Actions uses the same editor, with completions matched to the selected runtime (Docker Python, the bounded interpreter or the Nebius standard-library worker). Saved code in approvals, artifacts, notebook cells and the demo panel is highlighted read-only. The editor loads on demand (a separate 379 KB chunk), so the main bundle grows by only about 7 KB.

Verified in Chromium against an isolated data directory on port 4311, with the sandbox image built locally: creating Code focused the editor; `met` suggested `metric(title, value)` first; Escape closed suggestions and a second Escape inside the editor left the dialog open; an unclosed bracket was underlined; `Ctrl+S` saved; `Ctrl+Enter` prepared an attempt whose approval view showed highlighted code; **Allow & run** failed on `1 / 0` as intended, kept the earlier `Sum` metric, and underlined line 3 with a "Line 3 raised ZeroDivisionError" note. With a captured CSV and parameters, `df["` listed the CSV's three columns (including one with a space), `params["` listed both keys, and `df.gro` offered `groupby`. In an Action's Experiments tab the code and parameter editors rendered, `df["` listed the sample CSV columns, and switching to the Nebius runtime offered `export_csv(title, records)`. An uploaded notebook's code cell rendered with highlighting. The browser console stayed empty. An independent review then found that text typed during a save round-trip was overwritten (with the caret jumping to line 1) and that undo after loading a starter spliced old text into the new code. Both were fixed and rechecked in the browser: typing during `Ctrl+S` was kept with the caret in place, and undo after a starter restored the previous text. Suggestions no longer open inside comments. TypeScript and the Vite build passed. No unit tests were added or run, and no paid calls were made.

## Delivered behavior

- **Code** is created and revealed on the canvas first, then its editor opens; **Open content** or a double-click reopens it later. The editor has language/runtime, Save/Run/Stop, saved program, zero/one explicit full CSV, JSON parameters, outputs/errors, previous attempts and exact source/approval/runtime receipts. Python executes only in the existing Docker boundary. No selected dataset supplies neither a sample artifact nor `df`. Other languages retain source but have no execution adapter.
- Saved code/settings are ordinary undoable workspace content; browser-local unsaved drafts survive reopening. Layout does not consume content history or discard redo. Failed attempts retain program, logs/errors and valid bounded outputs produced before failure; earlier attempts stay immutable. Ask reviews the exact captured attempt and checks saved source/settings before admission. Resource/cancellation behavior and uncertainty accounting remain intact.
- **Notebook** opens a separate editor, connects to an existing user-managed loopback Jupyter/JupyterLab server, offers a token-free native interface link, and captures bounded saved Contents API snapshots. It never starts a kernel or executes imported cells. A bounded `.ipynb` upload supports the same saved-output capture when live access is unavailable.
- Choose a saved source version, cell and output checkboxes. Captures retain exact source/snapshot/cell/output hashes, path, stable cell ID or snapshot-index locator, reported count and capture time. These are external capture records with `executionObserved:false`; current kernel state, ordering, dependencies and code/output correspondence are not verified.
- CSV, JSON, text/logs, validated PNG and conservative safe SVG previews are supported. Unsupported MIME remains escaped, labelled inert JSON with exact download; HTML/scripts are never rendered. Connection tokens remain private server records/headers and are excluded from native URLs, public state and artifacts. The current token is rejected in notebook text even after JSON decoding or joined array normalization.
- Both block types use the existing artifact/history store. **Use as input** previews the exact version and same-project destination, records the selection receipt, and starts no recipient work. Only a full CSV becomes Code's single `df` input; other formats stay selected evidence. Source edits mark old output stale where evidence allows, without switching receiver/report versions or recomputing.
- **Use in report** preserves exact evidence IDs/hashes and external-versus-measured attribution in saved reports/exports. **Interpret selected output** prepares only the deliberately selected textual output and structural destination through the existing guide context/consent flow. No whole notebook, neighboring cells or project conversation is added implicitly; no live model request was verified.
- Blank/manual projects keep Assistant closed. Code/Notebook creation is directly discoverable on the existing canvas; **Discuss** retains the separate node conversation. Knowledge/Action/Group content remains compatible. Manual Code/Notebook cards show useful captured outputs without an inherited inference model badge.

## Unsupported behavior

C/Haskell execution, multi-CSV Python inputs, arbitrary container-file import, managed/embedded notebook launch, cross-project reuse, arbitrary agent delivery and managed Nemotron packaging/training are unsupported. Plot-to-model interpretation is unavailable in the text-only guide; deliberately selected text/CSV/JSON evidence can be prepared. External notebook permissions are its owner's responsibility and do not inherit ros.ai Docker isolation or accounting.

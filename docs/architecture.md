## Groups, evidence editors and agent seam · September 30–October 1

The October 1 connection follow-up adds compact native disclosure rows and explicit human-authored usage controls. `ConnectionBudgets` persists a stable grant per inference/search provider in additive `global_records`, independent of project deletion. A first explicit app grant is separate from historical environment ledgers; later numeric edits, pauses, credential changes and restarts retain its admissions. A saved app grant takes precedence over environment settings even when paused. `ExecutionService` rechecks its revision after model preparation and atomically reserves provider capacity and records project usage before dispatch. App inference is separate from the legacy combined sandbox grant; historical comparison mode fails closed for app allowances. There is no reset/delete-grant endpoint or model-visible grant tool.

`AgentBudget` additionally persists one live project Codex allowance, imports retained legacy project admissions and reserves full per-turn time/tool capacity. First enable captures the project's saved block/artifact IDs; numeric edits retain them, and explicit scope refresh validates current identities without resetting use. Pause takes precedence over the environment grant and interrupts an active turn. USD is not inferred for Codex. Native authentication and enforced restricted read access remain independent gates. These private routes are excluded from the public demo, and require JSON for mutations behind the local host/origin guard. UI saves never start inference. [Current setup](tool-connections.md).

`shared/groups.ts` defines explicit organizational Groups, grouping/ungrouping operations and the scientific node context used by approval. `Store.getProject` compatibly converts legacy nodes that own children, including saved content snapshots, while retaining identities, overview research and immutable execution records. `legacyKind` retains the original research role. Grouping and movement preserve each affected block’s effective model through saved overrides when inheritance would otherwise change; restoring inheritance is an explicit later choice. Group conversion is not a new execution or budget. `shared/blocks.ts` is a focused registry for note, Action, dataset, figure, code and report previews. Only Groups expand; research blocks open content. A collapsed Group has an item count and at most three explicitly selected artifact/hash highlights. No notebook, Office or database engine is implied by the registry.

`DataViewer` reads complete exact-version data and stores pagination, search/filter, sort and column visibility as browser preferences. `DerivedDataset` and `ArtifactEditingService` preview fixed transforms, compare source hashes again at commit and create new immutable derived artifacts with source and transformation provenance. They never rewrite an original dataset. `ArtifactViewer` provides zoom/download, figure presentation revisions and navigation to the producing attempt/captured inputs; retained code can prepare a separately approved analysis preview. `ReportEditor` and `shared/reports.ts` preserve inline author placement and exact evidence manifests. Report saves validate revision/source identities and update the block through undoable content mutations. HTML exports embed selected evidence; Markdown preserves exact evidence in its export appendix. Both add a process record built at export time by `report-record.ts`: every started analysis attempt on the cited blocks (program, input and output hashes, parameters, runtime and image, approval, and for failures the last traceback line with its program line), the researcher's decisions, and an AI-use statement from the project's own usage rows and Codex turns plus the researcher's line on AI used outside ros.ai. Records show file names, never local paths; full request text appears only when the export asks for it. Evidence labels separate measured results from input data, imported results, program code and execution logs, and a label that changed since the report was saved shows both. No arbitrary chart reconstruction or verified print-PDF engine is claimed.

A decision is a Text block labelled decision, linked to the blocks it rests on, so every agent reads it through the canvas listing and the report's process record lists it with who wrote it (the researcher, or the agent its links lead back to). Older projects kept a per-block decision log on `CanvasNode.decisions`; `Store.getProject` converts it once into decision blocks (`shared/decisions.ts`), keeping text, reason, basis versions and withdrawals in the block text, and records the conversion. Agents are still not offered the old field.

`AssistantService` persists a submitted user turn before stopped-project or Codex admission failures; `AssistantPanel` exposes pending submission, progress, Stop, persistent failures and uncertain browser-recovery state without automatic resubmission. Focus updates and submission share an ordered queue. Saved-context, direct-model and local-Codex response sources remain visible. The reported original silence was not reproduced; the changes do not establish its root cause.

`AgentRuntime` is separate from inference providers and Python execution backends. `CodexAgentService` connects through native app-server JSON-RPC, captures selected blocks/artifact versions and exposes only validated ros.ai read/proposal tools. Canvas effects use existing authority/store validation; deleting a selected Group requires every affected descendant to be selected. Report proposals remain pending until specific acceptance creates a derived report with model-claim provenance. Scope-bound sessions, observable tool/output/usage records, interruption and uncertain outcomes are implemented; host/external approvals are denied and unknown outcomes are not retried. A persistent fresh grant reserves full turn/time/tool allowances across its projects without replenishment. Admission policy, protocol support and effective runtime settings are reported separately.

Actual read-only initialize/account/config probes passed against Codex CLI 0.141.0 with ChatGPT sign-in; effective host-tool overrides and disabled inherited MCP servers were checked. No inference turn was authorized or sent. This installed schema lacks restricted read-root enforcement, so a read-only sandbox does not establish the required boundary. Execution fails closed both for that missing capability and for the absent fresh bounded grant. Streaming, cancellation and live dynamic-tool behavior remain unverified against inference. Native login is not copied into ros.ai provider credentials or treated as a spending grant. [Detailed adapter record](codex-local-agent-2026-09-30.md).

The shared database closed on server shutdown; durable deployment required a persistent volume.

## Continuous project conversation

`AssistantService` keeps one continuing project conversation separate from node chats and the earlier dataset-specific `ResearchSession` loop. A turn captures the user message, selected focus, reply, observable events, tool actions and references. Private durable step records preserve the model-visible messages, JSON schema, response, model metadata and usage identity; public state returns the conversational result rather than exposing the full trace on every poll. Saved focus changes attention, never permission or selected-input ownership.

Research memory preserves an immutable original question, later question formulations, decisions, findings, hypotheses and gaps. The outline combines these entries with current note relationships and captured execution evidence. References are checked against actual project identities. The frontend renders legacy project messages before the first assistant turn, avoiding duplicate display of the underlying messages stored for newer turns.

The assistant’s application-validated JSON contract can propose up to five notes, perform a bounded Tavily search in an existing note, propose an exact Docker or Nebius experiment against a captured dataset, or request explicit reuse of an immutable artifact. Owning services independently validate and govern each effect; pending proposed notes cannot be used as though already committed. Tool proposals do not grant execution. A turn permits at most two inference steps and at most three tool actions per response. No unrestricted filesystem, shell, installation or arbitrary network tool is exposed.

Direct-model context includes project-level history, focus, memory, note relationships, selected artifact versions and bounded evidence/error previews. It preserves relevant dataset/run identities and the latest question while checking the final serialized UTF-8 size, with explicit truncation/omission markers. Node conversations are not silently copied into project chat. If direct-model authorization or remaining budget is unavailable, a labelled saved-context response uses existing records without pretending a model was called. Explicit Codex selection instead persists its grant/enforcement blocker; it never substitutes a saved-context response as a successful Codex turn.

## Dataset-specific Action research loop

A `ResearchSession` stores a question, exact dataset artifact, node, bounded step count, run IDs, findings/suggestions and an observable phase. Each model step creates an ordinary immutable model run, retaining exact request and response. Its application-validated JSON proposes an experiment, a conclusion, or one related Action. This transport does not assume the historically failing named-tool request succeeds. Wrong schemas and unsolicited native tool calls do not execute.

Experiment proposals retain the originating model run plus actual code/data/parameter differences. The independent authority decides or escalates; the execution service captures inputs/code before starting a container. The next model call sees selected evidence and actual previous tables/metrics/errors with explicit truncation markers. It can propose a repair under remaining limits. No arbitrary graph traversal or neighboring conversation import occurs. A user-directed follow-up creates a linked session retaining previous findings and the same project counters.

Research context previews are bounded by their final serialized UTF-8 size, with numeric metrics prioritized and explicit truncation/omission markers. Full source artifacts stay intact. An edited experiment retains its research lineage and exact source dataset; its pending approval and actual output replace the superseded attempt for inspection. Changing the dataset in that lineage requires a separate Action. Related Action acceptance commits its resource admission, graph change, inherited data and session cursor atomically.

Related Action creation keeps a visible relationship explanation, proposal and undoable change. Ask and Approve for me ask before creating an Action, separately from starting work; Full access creates it without asking, and every addition stays undoable. New Actions inherit the project approval default and the nearest containing model setting. Manual changes remain direct. All accepted changes preserve canvas ownership rather than treating relationships as a pipeline.

## Runtime enforcement

Docker executes ordinary Python plus pinned research libraries with network disabled, read-only image and copied input mounts, no host source/home/socket mounts, non-root UID, dropped capabilities, seccomp/no-new-privileges, 512 MB memory, one CPU, 32 processes, bounded temporary files/output and 30-second wall timeout. Stop removes the whole unique container. An independent trusted watchdog attempts cleanup after server death. Full details and limitations are in [python-sandbox.md](python-sandbox.md).

This is container isolation using the Docker VM kernel, not a dedicated VM per experiment or a guarantee against runtime vulnerabilities. Python can access installed container files and spawn bounded child processes. It cannot access original source files, host shell, package-install service, external network or credentials through an exposed application tool. The old AST interpreter is a separate restricted language, not an OS sandbox. Missing Docker never triggers unrestricted execution.

## Recovery and interface

The store marks unfinished runs interrupted on restart and expires pending local approvals. Research sessions pause and require explicit continuation. Completed captured research-session model responses are reconciled instead of issuing another paid request; created experiment effects are matched to their source plan before another preview can be created. Active project assistant turns become interrupted and retain their captured state; a user follow-up is required rather than replaying their inference or tool actions. Unknown provider outcomes are never assumed successful. Browser closure alone leaves the local server working; laptop shutdown supplies no remote continuation.

The canvas uses one React Flow instance. Expanded parent boundaries, recursive groups, artifact cards and explicit highlights remain in one space. Four-sided handles support drag or click-to-connect. Root coordinates can be negative; the viewport imposes no persistence boundary. `savedCanvasPosition` snaps stored positions to the existing grid and subtracts content insets for children, clamping only nested positions to the parent content boundary. Expanded title/description edits save as one undoable mutation. Collapsed cards use a 408 px default width and expose a pointer/keyboard width control. A text-length heuristic supplies the initial footprint; `ResizeObserver` then measures actual wrapped content and clamps height to 224–420 px. The outcome paragraph scrolls within its area when necessary. Width and measured height feed routing, expanded-group bounds and arrangement. Manual insertion and server placement reserve a conservative 420 px height and each node's actual/default width, with the existing 72 px placement gap.

**Tidy** (`arrangeCanvas`) is an explicit presentation operation; it never runs on project load or enters content history. Blocks joined by relationships, projected onto the visible siblings in each parent scope, are laid out as trees read left to right: each block takes the column after its furthest parent and sits beside its first parent, centred on its own children, and a depth-first walk breaks cycles. Each set of linked blocks is its own tree, stacked in reading order; a Group's direct "contains" links are not counted. Unlinked blocks keep the reading-order grid below the trees, and uniquely numbered root stages keep their order. Column gaps fit the badge drawn on a relationship. Arrangement reserves measured cards, expanded groups and artifact footprints while keeping the root corner, including negative coordinates, and viewport steady. Repeated use is stable for unchanged visible content and sizes. Group ownership, saved widths, research content and connections are not rewritten by arrangement.

Automatic reflow reacts to settled displayed size or expansion changes after initial measurements establish a baseline. `createCanvasReflowPlan` records sibling separation order and deliberate gaps; recognized sources already above consumers retain that ordering. Manual moves and explicit Arrange establish a new spatial plan. The per-axis constraints discard redundant distant gaps that include intervening expanded frames, so collapse releases expansion-created space without flattening deliberate manual spacing. `reflowCanvas` settles children before their ancestors using measured card sizes and visible result footprints, preserves negative root anchors and enforces child containment. The client debounces size changes, defers during pointer/resize previews and arrangement animation, and persists only changed positions as one presentation batch. Stable signatures prevent repeated measurement writes; no reflow fits the viewport or changes focus. Failed saves surface a retry message instead of looping silently.

Research blocks now show one primary preview and explicit current status; all saved outputs remain accessible through content/details and the artifact viewer. Groups contain mixed blocks and expose up to three chosen exact-version highlights when collapsed. This replaces the earlier Show 2/4/All canvas result-card density controls. Dataset pagination lives in the full viewer and does not change captured data, history or the Group’s evidence selection. Arrangement and Group sizing use current measured frames and previews.

## Project folders · October 6, 2026

A project can have one folder on disk (`workspace_records` namespace `project-folder`, keyed by project). The database stays the source of history: runs, artifact versions and undo live there, and the folder holds the current content of each block as an ordinary file. `ProjectFolders` keeps the two in step.

- **Out:** `Store.onCommit` reports each committed canvas change (and each finished run) after the outermost transaction commits. A debounced pass then writes every block's file, Code outputs, `.ros-ai/project.json` and `<project>.canvas`. Notes, code, reports, datasets and notebooks are two-way; figures and outputs are written only by ros.ai.
- **In:** a recursive `fs.watch` plus a check every 3 s compares each file with its last agreed hash. A changed two-way file becomes one mutation labelled "Edited outside ros.ai", so Undo and history work as for any edit; datasets, notebooks and reports become new saved versions of the block (a dataset through a `file-import` run). A missing file is first looked for elsewhere in the folder by size and hash (a rename); otherwise the block is marked missing until the file is put back or the block is removed.
- **Safety:** paths are resolved inside the folder without following links, writes go through a temporary file and a rename, reads are size-capped and refuse links, and a file changed elsewhere is never overwritten before it has been read in. Removed and replaced files move to `.ros-ai/trash/<date>/`. The folder must not be a home, system or top-level folder, ros.ai's own data or code, or overlap another project; its device and inode are checked on every pass, so a moved or replaced folder stops syncing until it is reconnected.
- **Routes:** `GET /api/folders/suggest`, `POST /api/folders/choose` (the OS folder window), `POST /api/folders/open` (reconnect, rebuild from a manifest, or adopt a plain folder), and per project `GET|POST /api/projects/:id/folder`, `/folder/open`, `/folder/restore` and `/folder/add`. `POST /api/projects` accepts `folder`. None exist in public demo mode.

## Notebooks · October 7, 2026

A Notebook block's notebook lives in `workspace_records` under namespace `notebook-document`, keyed `<project>:<node>`: a revision number, nbformat metadata and cells with their ids, source, outputs and run numbers. `notebook-summary` feeds the canvas card. `notebook-previous` keeps the version that an import, an outside edit or a restore replaced, for Undo. `notebook-execution` records each finished cell: kernel session, run number, source hash, approval and one hash per output. With a project folder, the notebook is also `notebooks/<name>.ipynb`, written in nbformat's own layout (sorted keys, one-space indent, sources split into lines), so an unchanged file reads back byte for byte. A file changed elsewhere comes back through `NotebookService.fromFile` as a new revision. An older block without a notebook starts from its newest saved `.ipynb` snapshot.

`NotebookService` (`server/notebooks.ts`) keeps one kernel per running notebook, at most four. `NotebookKernelProcess` (`server/notebook-kernel.ts`) starts `docker run -i` on the research image with no network, a read-only root, all capabilities dropped, no new privileges, 2 GB of memory, 2 CPUs, 128 processes and `noexec` temporary folders. With a project folder, the folder is mounted read-only and `outputs/<notebook>/` writable. The Python side (`sandbox/notebook_kernel.py`, passed with `-c`) speaks JSON lines: execute requests in; stream, display, result, error and done messages out. It keeps one namespace that starts with only `__builtins__` and `display`, turns open matplotlib figures into PNG outputs, caps output sizes, and turns SIGINT into KeyboardInterrupt, which Stop sends with `docker kill --signal=INT`. Containers carry an owner label derived from the data folder, so leftovers are removed at start-up; every kernel stops at shutdown, when its block is removed, or after 30 idle minutes.

Runs queue per notebook. Before a cell is queued it passes `Authority` under the block's mode. Ask needs that cell's exact fingerprint (project, block, cell and source hash) approved. Approve for me sends the cell to the automatic reviewer together with the names defined by the cells queued before it, so a `df` from an earlier cell is not unknown. Full access admits every cell. The first cell that needs approval stops the queue, and the screen shows its check card.

The browser follows a notebook through `GET …/notebook/events`, a server-sent event stream of kernel state, cell states (queued, running, done, cancelled), outputs, streamed text, clears and new revisions. Saves are `PUT …/notebook` with the revision they started from; an outdated one gets 409, and the screen asks which version to keep. The other routes are `run`, `interrupt`, `restart`, `clear`, `import`, `restore`, `outputs` (save one output as a result) and `figure` (the card's newest figure, by hash). None exist in public demo mode.

Saving an output as a result compares its hash with the recorded execution. A match becomes a `notebook-cell-output` (a measured result, with session and execution ids); anything else becomes an `external-notebook-output`, like the October 2 captures. The screen never inserts HTML: Markdown and outputs are drawn as React elements, HTML tables are read through an inert `DOMParser`, SVG is shown as an image, and pictures on the web stay links.

## Notion page block and one block per row · October 21, 2026

A Notion block (blockType `notion`, kind External) now shows a page as well as a database. `NotionView.kind` (`page` or `database`) is learnt at the first read and saved on the block; an older block without it is a database. Nothing of the page is saved: `NotionViews.read` (src/server/notion-view.ts) classifies a link with one `notion-fetch` through the hosted Notion connection and returns a `NotionTable` or a `NotionPage` (src/server/notion-page.ts): the page's properties in the order of its database (dates joined, checkboxes as Yes or No, people by name through `notion-get-users`, relations as links), its content as the plain Markdown the canvas renders (Notion's own tags for headings, lists, to-dos, quotes, callouts, tables and media become their Markdown forms; columns and other containers contribute only what they hold) and the database or page it lives in. Reads are reused for ten minutes and kept in the project cache like a database's rows. The card shows the first four filled fields and a few lines of text; the block view shows every field and the whole text.

One block per row: the footer of a database block (card and block view) offers it, asks once, and `rowBlockOperations` (src/shared/notion-rows.ts) adds one page block per row the block shows (so its filter applies), titled by the row, in the same Group, laid out beside the database block, each linked from it with the caption `row`. Rows already on the canvas as page blocks are skipped; at most 50 rows go in one go, and narrowing the filter reaches the rest. A database read always carries the title column (`NotionTable.titleColumn`) for this. For Ros and the other agents, `ros_read_canvas` on a Notion block returns what the canvas shows: a page's fields and text, or a database's first 50 rows (title and link, `onCanvas` when a page block exists) with the instruction to propose an addNode per row plus an addConnection labelled `row` through `ros_propose_canvas`, whose operations cap rose from 20 to 120 for this. No tool name or argument changed.

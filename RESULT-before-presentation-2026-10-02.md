## Delivered behavior

- **Research model:** built-in Nebius/OpenAI and registered personal compatible APIs or user-managed loopback model servers are selectable with maker/model/destination labels. Stable connection identities, cumulative accounting, project defaults and block inheritance remain. Full endpoint paths and write-only keys stay in an owner-only server file; readable status contains only origin, key presence, declared models/caps and allowance counters. Connection configuration and explicit usage enable/pause are separate actions, with no probe or model call on save.
- **Workspace guide:** Review workspace has Structure, Inputs and outputs, and Conclusion intents. A registered guide connection/model is chosen independently of research. Structural aliases exclude actual IDs, titles, descriptions, relationship wording, chats, memory, code and evidence. Selected fields, block texts and exact saved artifact versions/excerpts can be deliberately included. An immutable manifest records scope, hashes and omissions. Destination consent binds the displayed connection/model/revision; changed terms block before dispatch. No hidden second-model review or cloud fallback is introduced.
- **Suggestions:** the guide may propose blocks, Groups, moves, meaningful relationships or specific saved inputs. The whole action plan is validated against captured aliases, evidence and current project revision. Canvas changes use the existing approval/provenance/history path; Ask retains specific approval. Input reuse is a separate explicit acceptance of a saved version and does not run another node or import future outputs.
- **Replies and completion evidence:** ordinary text remains readable without action JSON. Bounded visible response, reported usage, actual model, finish reason and transport metadata are retained before application validation. A whole valid JSON object or JSON fence can supply strictly validated actions; malformed/partial actions never apply guessed changes or memory. Fatal model/protocol errors retain available receipts and review linkage. No paid formatting retry is automatic. The old failed Nebius reply was never saved and cannot be reconstructed retrospectively.
- **Admission and Stop:** registered connections enforce complete request bytes, response bytes, requested output cap, deadlines and concurrency. Local calls debit no provider USD in ros.ai but consume cumulative connection requests and shared project model calls. Remote calls need declared upper token rates, connection USD/request capacity and project spending capacity. Unaudited remote accounting reserves twice the full declared context at both input/output rates because total billable reasoning caps are unverified. Failure/Stop/restart retain reservations and uncertainty; edits/removal/re-addition never replenish usage. One guide review runs at a time; Stop and project Stop retain terminal reviews.

## Limits and next delivery stages

This is a compatible scalar-text HTTP adapter, not support for every inference protocol. Its declared tokenizer, model capacity, prices and endpoint handling of output limits are unverified; actual provider invoices may require a provider-specific audited adapter. A loopback server may proxy elsewhere or have tools of its own, so it is labelled **local processing unverified**. ros.ai bounds its request transport; it does not establish OS isolation for a user-managed runtime.

No managed Nemotron weights/runtime download, verified offline bundle, target-laptop performance measurement or fine-tuned checkpoint is shipped. The guide currently requires a user-configured server. The design's base-model evaluation and conditional adaptation remain later stages; no private project is collected as training data. Additional CLI protocols remain focused adapter work. Existing Codex native runtime/grant controls remain separate; the installed restricted-read isolation gate still blocks embedded turns. Existing Claude and Google limits remain documented in the prior result.

No paid inference, authenticated provider verification, subscription CLI turn, model download/install/training, account change, purchase, deployment, public write, push, commit, goal or automation occurred. Normal commands remain npm run build and npm start. Repository instructions and dated pre-event work are preserved.
